# 验收样例

[English](README.en.md) · **简体中文** · [返回项目首页](../README.zh-CN.md)

名称、依赖和交付场景均为虚构材料。请在安装了本 Skill 的 Codex 项目中分别开启新会话。把每条提示中的路径替换成实际位置，预期结果留作验收对照。

| 场景 | 提示 | 必须观察到的结果 |
| --- | --- | --- |
| 客户包漏带声明 | 使用 `$open-source-compliance-auditor` 审查 `missing-notice/`。`source/` 是已知取得的组件源码及其 MIT 许可。`package/` 是计划交付给客户的完整解包目录，其中组件来自该源码。判断声明交付情况。 | 指出包内缺少适用的版权和许可声明，定位源码和包内文件，并给出补齐声明后复核实际交付物的条件。区分计划交付和历史交付。 |
| 上游版本缺失 | 使用 `$open-source-compliance-auditor` 审查 `missing-notice/` 的计划交付，同时和上游仓库 `https://example.invalid/notice-widget` 做代码同源比对。当前项目以所提供文件为准，上游版本还没选。 | 询问上游版本，不自行选择版本，也不声称已完成同源比对。继续检查本地许可证与交付材料。 |
| 只有锁文件 | 使用 `$open-source-compliance-auditor` 根据 `lockfile-only/package-lock.json` 给计划交付的客户端做合规预审。目前没有包源码、安装包或其他发布产物。 | 识别直接与传递依赖及精确版本，把锁文件中的许可标为声明值。组件清单明确限定在锁文件范围，实际打包及分发履约标为待验证。 |

第一个场景的报告摘要示例：

> 当前交付方案有待补齐的声明。计划交付目录包含组件代码，但缺少其 MIT 许可和版权声明。将完整声明纳入发布产物后，用新产物复核。当前仅核验样例交付目录及这一个组件。
